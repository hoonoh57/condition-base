# 구현 결정 · 2026-09-17

- 사용자 요청에 따라 실행 기반뿐 아니라 5개 라우트·트랜잭션·화면·파생 지표까지 연결했다.
- 연구 쓰기는 srb_lab으로 분리했다. 기존 srb_core 데이터와 정의는 웹에서 변경하지 않는다.
- 읽기/빌드/실험/승격의 MySQL 역할을 분리하고 설치 전용 ADMIN 계정을 추가했다.
- 원천 자료가 없는 상장주식수·상장상태·수급은 known_date가 있는 입력 테이블로 받는다.
  원천 값이나 시장경보 규칙을 만들어 채우지 않는다.
- 지표 빌드는 BUILD 계정을 사용하며 SQL 주석/문자열을 보존해 문장을 분리한다.
- 빌드 상태와 고유 build_id를 기록한다. 실패한 파생 결과는 API에서 사용하지 않는다.
- P0 결과를 파일에 저장하고 원천 기준일과 일치하는 보고서 검토 후에만 CLI 빌드를 허용한다.
- 스택 편집은 새 버전·사전 가설·시도 회계·스냅샷을 하나의 트랜잭션에 저장한다.
- 동시 버전 번호는 전략 잠금과 최신 버전 잠금 조회로 직렬화한다.
- 부분 전방 데이터나 구간 경계를 넘은 MFE를 실패 표본으로 계산하지 않는다.
- 모바일 표는 수평 스크롤로 보존하고, 조회 실패 시 이전 측정 숫자를 현재 구간 결과로 보여주지 않는다.
- PowerShell 안내에서 cmd 전용 cd /d 및 < 입력 리디렉션을 제거했다.
- 격리 MySQL 9.7.1과 실제 reader/lab/build 권한으로 SQL, 회계, 경계, 동시성, 롤백을 검증했다.
  Chrome에서 전략 생성 → 조건 추가 → 무료 탐색 → 차트 → 이력/자료 화면을 검증했다.
- 실제 .env의 읽기 계정은 검증 시 ER_ACCESS_DENIED_ERROR였다. 운영 원천 P0와 빌드는 실행하지 않았다.
